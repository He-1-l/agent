# 自习室管理 Agent

基于自习室预约系统业务，手写 function-calling 循环，让模型自主选择工具完成多步查询。

## 项目背景

自习室预约系统的规则文档和统计数据是分开的：

- **规则**（签到时限、信用分、违约扣分）写在文档里，模型不知道
- **统计**（谁违约几次、各时段预约量）存在数据库里，模型看不到
- **算术**（100 - 3×5）模型心算会错

一个混合型问题，比如「违约最多的人信用分还剩多少」，需要**查数据库 → 查规则 → 做计算**三步才能答。

纯 RAG 只能检索文档，做不到这件事。这就是要做 Agent 的原因。

## 架构

```
                    用户提问
                        │
                        ▼
              ┌──────────────────┐
              │  LLM (qwen-plus) │
              │   tools=3 个     │
              └────────┬─────────┘
                       │
              ┌────────┴────────┐
       无 tool_calls        有 tool_calls
              │                 │
              ▼                 ▼
         最终回答          ┌─────────────┐
         (循环结束)        │ 工具分发     │
                          └──────┬──────┘
                 ┌───────────────┼───────────────┐
                 ▼               ▼               ▼
          search_rules      query_stats      calculate
          Chroma 向量检索    SQLite 聚合      正则白名单
          距离 < 0.85 才用    3 个 metric      + eval
                 │               │               │
                 └───────────────┴───────────────┘
                                 │
                        结果回灌 messages
                        (异常转 error 字符串)
                                 │
                                 └──> 下一轮（最多 8 步）
```

## 三个工具

| 工具 | 补什么能力缺口 | 实现 |
|---|---|---|
| `search_rules` | 非结构化知识 | Chroma + DashScope Embedding，余弦距离 < 0.85 才返回 |
| `query_stats` | 结构化数据 | SQLite `GROUP BY` 聚合，3 个固定 metric |
| `calculate` | 精确算术 | 正则白名单（只放行数字与 `+ - * / ( )`）+ `eval`，禁用 builtins |

## 实测结果

四个场景，都是真实运行输出。

### 场景 1：多工具串联（3 步）

**问**：2026年10月违约最多的是谁？按规则他的信用分还剩多少？

```
[step 1] query_stats({"metric": "violator_ranking"})
         -> 张伟:3, 李娜:2, 王强:1
[step 2] search_rules({"query": "违约扣信用分标准"})
         -> 违约规则：每次扣 5 分；信用分规则：初始 100 分
[step 3] calculate({"expression": "100-3*5"})
         -> 85

A: 张伟违约 3 次，每次扣 5 分，初始 100 分，当前 85 分。
   数据来源：violator_ranking 统计 + 规则文档「违约规则」「信用分规则」条款
[步数 4 | tokens 4054 | 结束原因 final]
```

### 场景 2：单工具

**问**：签到的时间窗口是多长？

```
[step 1] search_rules({"query": "签到时间窗口"})
         -> 签到规则：预约时段开始后 15 分钟内可签到（距离 0.471）

A: 签到窗口为预约时段开始后 15 分钟内。超时未签到，系统自动释放座位并记一次违约。
[步数 2 | tokens 1570]
```

### 场景 3：不该用工具（0 次调用）

**问**：你好，你能做什么？

```
[步数 1 | tokens 774 | 无工具调用]
A: （自我介绍 + 举例说明能回答哪几类问题）
```

### 场景 4：知识库没有的内容（应拒答而非编造）

**问**：图书馆的开放时间是几点？

```
A: 图书馆的开放时间不在我的知识库或可调用工具范围内。
   建议查阅图书馆官网或联系前台。
[步数 1 | tokens 676 | 无工具调用]
```

**这一条是刻意设计的边界**：8 条规则里没有「图书馆开放时间」，模型必须如实说不知道，不能编。

## 三层防死循环

| 层 | 机制 | 代码位置 |
|---|---|---|
| 1 | 步数硬上限 8 | `for step in range(1, MAX_STEPS + 1)` |
| 2 | 同工具同参数连续调用检测 | `if sig == last_sig: 注入错误提示` |
| 3 | 单会话 token 上限 20000 | `if total_tokens > MAX_TOTAL_TOKENS` |

**第 2 层最有效**，因为死循环的典型形态就是模型反复用同样的参数查同一个东西。

## 工具异常不往外抛

```python
def _safe_call(name, args):
    try:
        return str(fn(**args))[:MAX_TOOL_CHARS]
    except TypeError as exc:
        return json.dumps({"error": f"参数不匹配: {exc}"})
    except Exception as exc:
        return json.dumps({"error": f"{type(exc).__name__}: {exc}"})
```

所有异常转成 `{"error": "..."}` 字符串回灌给模型，让它自己决定重试还是换思路。单点工具故障不会让整个对话崩掉。

## 检索阈值 0.85 的来源

实测距离分布（8 条规则，11 个测试问题）：

| 类型 | 距离范围 | 举例 |
|---|---|---|
| 相关 | 0.38 – 0.95 | 「我迟到了会怎样」→ 违约规则（0.741） |
| 无关 | 0.92 – 1.26 | 「今天天气」→ 1.127 |

取 0.85 作阈值：相关组里只有「打卡怎么弄」（0.947，同义词）会漏，无关组全部正确拒答。

## 为什么手写循环，不用 LangChain AgentExecutor

框架把终止条件、异常处理、重试都封装了，出问题无法定位。手写之后能明确回答：

- **终止**：模型这一轮不返回 `tool_calls` 就是最终答案；超过 8 步强制中断
- **异常**：工具抛异常不往外抛，转 error 字符串回灌
- **打转**：同工具同参数连续两次，注入错误打断
- **成本**：累计 token 超 2 万就停，工具结果单条截断 2000 字符

## 已知限制

1. **检索是关键词无关的语义匹配**，同义词覆盖不全（「打卡」匹配不到「签到」，距离 0.947 超过阈值）
2. **`calculate` 用的是正则白名单 + `eval`，不是 `ast` 解析**。正则能挡住 `__import__` 这类注入，但不如 `ast` 严格
3. **数据库是 16 条假数据**，只覆盖 2026 年 10 月，问「本周」「上个月」会返回 `found=false`
4. **没有多轮对话**，每次调用都是独立的


```bash
python loop.py "2026年10月违约最多的是谁？按规则他的信用分还剩多少？"
```
