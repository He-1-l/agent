# LangChain + RAG 技术手册

## 什么是 RAG

RAG 全称 Retrieval-Augmented Generation，中文叫「检索增强生成」。

核心思想：大模型的知识有截止日期，也不了解你的私有数据。  
RAG 的做法是——先从你的文档库里检索出相关内容，再把内容作为上下文喂给大模型，让它基于这些内容回答。

一句话概括：**先查资料，再回答问题**。

## RAG 的完整流程

RAG 分为两个阶段：

### 阶段一：索引（离线，只做一次）

1. 加载文档（Load）：把 PDF、Word、Markdown 等读成纯文本
2. 切分（Split）：把长文本切成小块（chunk）
3. 向量化（Embed）：把每个 chunk 通过 Embedding 模型转成向量
4. 入库（Store）：把向量存进向量数据库

### 阶段二：检索与生成（在线，每次提问都做）

1. 用户提问
2. 把问题也转成向量
3. 在向量库里找最相似的 Top-K 个 chunk
4. 把问题和这些 chunk 一起发给大模型
5. 大模型基于 chunk 内容生成答案

## 文档切分策略

chunk_size 和 chunk_overlap 是两个最重要的参数。

- chunk_size：每个文本块的最大长度，通常按字符数计算
- chunk_overlap：相邻块之间的重叠部分，防止句子被从中间切断

经验值：

- chunk_size 设为 500-1000 字符
- chunk_overlap 设为 chunk_size 的 10%-20%

如果 chunk 太大，检索精度下降，因为一个块里混了太多主题。  
如果 chunk 太小，语义不完整，模型难以理解上下文。

## 向量检索原理

Embedding 模型把文本转成一个高维向量（比如 1024 维）。  
语义相近的文本，它们的向量在空间中的距离也相近。

常用的相似度计算方式是余弦相似度（Cosine Similarity），取值范围 -1 到 1，越接近 1 越相似。

检索时，把用户问题也转成向量，然后计算它和库中所有向量的相似度，取最高的 K 个。

## 为什么要用 Rerank 重排

初次检索（粗排）追求速度，通常用向量相似度快速召回几十个候选。  
但向量相似度并不总能准确反映语义相关性。

Rerank（重排）是一个更精细的模型，它对召回的候选重新打分排序，精度更高但速度更慢。

典型做法：粗排召回 20 个，Rerank 精选 5 个。

实测中，加入 Rerank 通常能把检索准确率提升 15-20 个百分点。

## 如何防止幻觉

RAG 最大的风险是模型编造答案。三种常见手段：

1. 提示词约束：明确要求「只根据提供的资料回答，资料中没有就说不知道」
2. 返回出处：答案中标注引用的文档名和页码，便于人工核查
3. 相关性阈值：如果检索到的内容相似度低于阈值，直接判定为「无相关资料」

## 记忆管理

多轮对话的记忆本质是一个不断增长的 messages 列表。  
每次请求都要把完整历史发给模型，因此长对话成本很高。

常见压缩策略：

- 滑动窗口：只保留最近 N 轮
- 摘要压缩：用模型总结前文，用摘要替代原文
- 持久化检索：把历史存进数据库，需要时检索回来

## 常见踩坑点

1. 忘记设置 override=True，导致 .env 配置被系统环境变量覆盖
2. chunk_overlap 设为 0，句子被切断，检索质量下降
3. 不设置相似度阈值，无关问题也会硬凑答案
4. 把 key 提交到 GitHub，造成泄露
