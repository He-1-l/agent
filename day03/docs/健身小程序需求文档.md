# 健身打卡小程序 · 产品需求文档

## 一、项目概述

本项目是一款面向健身爱好者的微信小程序，名为「健身打卡」。  
核心目标是帮助用户养成健身习惯，通过打卡、勋章、排行榜等激励机制提升用户黏性。

技术架构采用前后端分离：

- 前端：微信小程序（WXML / WXSS / JavaScript）
- 后端：Spring Boot + MyBatis-Plus
- 数据库：MySQL

## 二、核心功能模块

### 2.1 课程模块

用户可以浏览健身课程列表，点击进入课程详情页查看动作要领、时长、难度等级。  
课程分为三个难度：入门、进阶、高手。

### 2.2 打卡模块

用户每天可以提交一次打卡记录，记录内容包括打卡日期、运动时长、运动类型、备注。

打卡规则：

- 每个自然日只能打卡一次
- 打卡时间以服务器时间为准，避免用户篡改本地时间
- 连续打卡天数从最近一次打卡往前推算，断卡后重新计算

### 2.3 勋章模块

用户达成特定条件后自动获得勋章。已设计的勋章包括：

- 初出茅庐：完成首次打卡
- 坚持不懈：连续打卡 7 天
- 百炼成钢：累计打卡 100 天
- 全勤达人：单月打卡满 30 天

勋章一旦获得不可撤销，永久保存在用户勋章表中。

### 2.4 排行榜模块

排行榜分为周榜和总榜：

- 周榜：统计本周内所有用户的打卡次数，按次数降序排列
- 总榜：统计用户历史累计打卡次数

排行榜每 10 分钟刷新一次，采用定时任务实现。

## 三、技术实现要点

### 3.1 用户登录

采用微信开放平台的 OpenID 登录方案。  
用户在小程序端调用 wx.login 获取 code，后端用 code 换取 openid 和 session_key。  
后端通过 openid 查询用户是否已注册，未注册则自动创建账号。

### 3.2 分层架构

后端代码按 Controller – Service – Mapper 三层组织：

- Controller 层：接收 HTTP 请求，做参数校验，返回统一响应体
- Service 层：编写业务逻辑，如连续打卡天数计算
- Mapper 层：基于 MyBatis-Plus，负责数据库读写

统一响应体 Result 包含三个字段：code（状态码）、msg（提示信息）、data（业务数据）。

### 3.3 跨域处理

由于小程序端与后端域名不同，需要配置 CORS 允许跨域请求。  
通过自定义 CorsConfig 配置类实现，允许所有来源、所有方法和所有请求头。

## 四、数据表设计

主要数据表：

- user 表：id、openid、nickname、avatar、create_time、update_time
- checkin_record 表：id、user_id、check_date、duration、sport_type、remark
- course 表：id、title、cover、duration、difficulty、description
- medal 表：id、name、description、icon、condition_type、condition_value
- user_medal 表：id、user_id、medal_id、achieve_time

## 五、性能优化

1. 排行榜查询使用索引优化，user_id 和 check_date 建立联合索引
2. 课程列表采用分页查询，避免一次加载全部数据
3. 勋章判定逻辑放在打卡成功后异步执行，不阻塞主流程
