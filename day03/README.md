## 二、Rerank 是什么

**两阶段检索：**

```
用户提问
   ↓
① 粗排（向量检索）：快，从全库召回 15-30 个候选
   ↓
② 精排（Rerank）：慢但准，从候选里精选 4-5 个
   ↓
③ 把精选的内容喂给大模型
```

**为什么要两阶段？**

- **只用向量检索**：快，但精度有限。它看的是"字面/语义相似"，不总能抓住"真正能不能回答问题"
- **全库都用 Rerank**：太慢太贵。假设库里有 10 万块，逐块重排要几十秒
- **两阶段**：兼顾速度和精度，**这是工业界标准做法**

**实测例子**（`run1.bat` 的输出）：

```
【问题】chunk_overlap 设成多少合适？

粗排 Top-3：
   1. [距离 0.6661] 经验值：chunk_size 设为 500-1000 字符...
   2. [距离 0.7908] ### 阶段二：检索与生成...
   3. [距离 0.8474] ## 常见踩坑点...

精排 Top-3：
   1. [重排分 0.7940] 经验值：chunk_size 设为 500-1000 字符...
   2. [重排分 0.3192] ## 常见踩坑点...         ← 从第3升到第2
   3. [重排分 0.2759] ### 阶段二：检索与生成...  ← 从第2降到第3
```

**Rerank 纠正了向量检索的排序错误。**

## 三、⭐ 今天最重要的发现（诚实实验）

### 先说结论

**在小知识库上，Rerank 完全没有增益。**

| 知识库规模 | 无 Rerank | 有 Rerank | 提升 |
|---|---|---|---|
| **14 块**（默认 docs） | 81.2% | 81.2% | **+0.0 个百分点** |
| **272 块**（docs_large） | 72.9% | 75.0% | **+2.1 个百分点** |

### 为什么小库上没效果？

**因为粗排把整个库都召回了。**

```python
COARSE_K = 15        # 召回 15 个
知识库总共 = 14 块    # ← 全库召回！
```

**当候选集就是全集时，Rerank 怎么排都一样——能选的就那些。**

**这是真实的工程规律：Rerank 的价值随候选集规模增大而体现。**

### 为什么这件事很重要

**面试官最讨厌两种人：**

1. **堆技术不懂原理**：简历写一堆时髦词，问细节就卡壳
2. **编造数据**：说"Rerank 提升 30%"，追问测试集设置就露馅

**你现在的优势是：你有一组真实的实验数据，而且知道它的边界条件。**

## 四、面试怎么讲这个项目

**Q1：你为什么加 Rerank？**

> 向量检索是"粗排"，它基于向量距离找相似内容，速度快但精度有限。
> 我加了 Rerank 做"精排"，用更精细的模型对候选重新打分。
> **但我实测发现，在小知识库上它没带来提升**——因为粗排召回数接近库总量，
> 候选集等于全集。扩到 272 块后，命中率从 72.9% 提升到 75.0%。

**Q2：那你还加它干什么？**

> 因为知识库会增长。现在 14 块不需要，但真实场景动辄几万块，
> 那时 Rerank 就是必需的。**架构上要预留这个能力。**
> 同时我也做了降级处理——Rerank 调用失败时自动回退到纯向量检索。

**Q3：你怎么评估检索质量？**

> 我建了一个 8 题的评估集，每题标注"标准答案必须包含的关键词"，
> 然后统计生成答案里关键词的命中率。
> 这比单纯看"答对/答错"更细粒度——因为很多答案是"部分正确"的。

**Q4：还有什么可以优化的？**

> 三个方向：
> ① 混合检索（向量 + BM25 关键词检索）取长补短
> ② Query 改写，把用户口语化问题转成更适合检索的形式
> ③ 调 chunk_size 做对比实验，找最优切分粒度

## 五、代码里的关键设计

### 1. 两阶段检索

```python
def retrieve(question: str, use_rerank: bool):
    # 粗排：向量检索，召回 15 个
    coarse = vectorstore.similarity_search_with_score(question, k=COARSE_K)

    if not use_rerank:
        return coarse[:FINE_K]          # 对照组

    # 精排：Rerank 重排，精选 4 个
    docs = [d.page_content for d, _ in coarse]
    resp = TextReRank.call(model="gte-rerank-v2", query=question,
                           documents=docs, top_n=FINE_K, api_key=API_KEY)
    return [(coarse[it.index][0], coarse[it.index][1])
            for it in resp.output.results]
```

### 2. 优雅降级（重要）

```python
if resp.status_code != 200:
    print("⚠️ Rerank 调用失败，降级为只用向量检索")
    return coarse[:FINE_K]
```

**为什么重要？** 线上服务不能因为一个可选组件挂掉就整体不可用。**这是工程意识。**

### 3. 可复现的评估

```python
TEST_SET = [

```
