## 二、RAG 是什么（30 秒版）

**一句话：先查资料，再回答问题。**

```
用户提问
   ↓
① 把问题转成向量
   ↓
② 在知识库里找最相似的几段文字      ← 检索
   ↓
③ 把这些文字 + 问题一起发给大模型    ← 增强
   ↓
④ 模型基于这些文字回答              ← 生成
```

**为什么要这么做？**

大模型有两个硬伤（你在 Day 1 已经亲眼见过）：

1. **不知道你的私有数据**（你们公司的文档、你的项目文档）
2. **会编造**（问它"现在几点"，它编了个"2025年4月5日"）

RAG 就是**把资料塞给它，让它照着答**，两个问题一起解决。

## 三、三个核心概念（必须能讲出来）

### 1. 向量（Embedding）

**文字变成一串数字。**

```
"苹果手机"  →  [0.12, -0.35, 0.88, ...]   (1024 个数字)
"iPhone"   →  [0.11, -0.33, 0.90, ...]   (很接近！)
"今天天气"  →  [0.87, 0.42, -0.15, ...]  (差很远)
```

**关键**：语义相近的文字，向量也接近——**哪怕字面完全不同**。

这就是为什么你搜"苹果手机"能找到写着"iPhone"的文档，**传统关键词搜索做不到这点**。

### 2. 距离（Score）

**数字越小 = 越相似。**

看 `run2.bat` 的实测结果：

| 问题          | 最相似片段距离   | 判断    |
| ----------- | --------- | ----- |
| 连续打卡天数怎么计算？ | **0.675** | ✅ 相关  |
| 什么是 RAG？    | **0.555** | ✅ 相关  |
| 今天股市怎么样？    | **1.255** | ❌ 不相关 |

**看出规律了吗？** 相关问题的距离在 0.5-0.9，无关问题在 1.2 以上。

**所以设一个阈值（我们用 1.0）**：距离超过 1.0 就判定"没找到资料"，直接拒答。

**这就是"防幻觉"的第一道防线。**

### 3. Chunk（切块）

长文档要切成小块才能检索。

**两个参数**：

- `chunk_size=300`：每块最多 300 字符
- `chunk_overlap=50`：相邻块重叠 50 字符

**为什么要重叠？** 防止句子被从中间切断。

```
块1: ...打卡规则：每个自然日只能打卡一次，打卡时间以服务
块2: 器时间为准，避免用户篡改本地时间...
      ↑ 句子被切断了
```

**有重叠后**，块1 的结尾和块2 的开头会重复一部分，保证至少有一块包含完整语义。

## 四、这个项目的三个亮点（简历直接用）

### 亮点 1：答案可溯源

每个 chunk 都记录了 `source`（来自哪个文件）和 `chunk_id`（第几块）。

回答时会附上出处：

```
【回答】连续打卡天数从最近一次打卡往前推算，断卡后重新计算。
【出处】· 健身小程序需求文档.md
```

**为什么值钱？** 企业 RAG 的最低要求不是"能回答"，而&#x662F;**"答案能追溯到原文"**。因为要人工核查。

### 亮点 2：能拒答（防幻觉）

**测试对比：**

| 问题          | 系统行为                      |
| ----------- | ------------------------- |
| 连续打卡天数怎么计算？ | ✅ 正常回答 + 出处               |
| 今天北京天气怎么样？  | ✅ **拒答**："根据现有资料无法回答这个问题" |

**这就是企业 RAG 和玩具 RAG 的分界线**：

- 玩具：什么问题都硬答，经常瞎编
- 企业：不知道就说不知道

### 亮点 3：提示词约束

```
1. 只根据上面的资料回答，不要使用你自己的知识
2. 如果资料中没有相关信息，直接说"无法回答"，不要编造
3. 不要写"根据资料"这类开头
4. 不要编造资料中没有的数字、名称或结论
```

**提示词是第二道防线**（第一道是阈值过滤）。**两层一起用才稳。**

## 六、面试会问什么（准备答案）

**Q1：为什么要切分？不能整篇塞进去吗？**

> 两个原因：一是模型上下文长度有限；二是整篇塞进去检索时无法定位到具体段落，精度差。切成小块才能精准召回相关内容。

**Q2：chunk_size 怎么定？**

> 太大则一块混多个主题、检索不准；太小则语义不完整。经验值是 300-1000 字符，overlap 取 10%-20%。我实测 300 效果不错（可以讲你的实测数据）。

**Q3：怎么防止模型编造答案？**

> 三层：① 相似度阈值过滤，检索不到相关内容直接拒答；② 提示词明确约束"只根据资料回答"；③ 返回出处，便于人工核查。

**Q4：什么是向量？为什么能检索？**

> Embedding 把文本映射成高维向量，语义相近的文本在向量空间中距离也近。检索时把问题也向量化，算余弦相似度，取最相似的 Top-K。所以能实现"苹果手机"匹配到"iPhone"这种语义检索。

**Q5：为什么需要 Rerank？**（加分项）

> 向量检索（粗排）追求速度，精度有限。Rerank 用更精细的模型对候选重新打分，精度更高但更慢。典型做法是粗排召回 20 个，Rerank 精选 5 个，通常能提升 15-20 个百分点。
